# Contributing to Dagychu Community

Thank you for your interest in contributing to Dagychu Community.

## Before contributing

Please use GitHub Issues to discuss significant changes before investing substantial implementation work. This helps avoid duplicate work and changes that conflict with the product architecture.

For security vulnerabilities, do **not** open a public issue. Follow [SECURITY.md](SECURITY.md).

## Contributions

Contributions may include:

- bug fixes;
- documentation improvements;
- tests;
- examples;
- compatibility fixes;
- focused product improvements.

A contribution should:

- have a clear purpose;
- avoid unrelated refactoring;
- include or update tests where practical;
- update documentation when behavior changes;
- preserve backward compatibility unless a breaking change is explicitly accepted.

## License of contributions

Unless you explicitly state otherwise, any contribution intentionally submitted for inclusion in Dagychu Community is submitted under the terms of the Apache License 2.0, as described in Section 5 of that license.

By submitting a contribution, you represent that you have the right to submit it under those terms.

## Pull requests

Before opening a pull request:

1. make sure the change is focused;
2. run the relevant tests;
3. describe the problem being solved;
4. explain notable implementation decisions;
5. identify breaking behavior or migration requirements;
6. link the relevant issue when one exists.

Maintainers may request changes or decline contributions that do not fit the current product direction.

## Enterprise and proprietary code

Do not submit proprietary Raideria code, customer code, credentials, private infrastructure configuration, or Enterprise-only source material to the public Community repository.

If you are unsure whether material is appropriate for the public repository, do not publish it until a maintainer has reviewed it.
